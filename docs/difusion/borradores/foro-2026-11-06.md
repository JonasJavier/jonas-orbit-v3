The home page of my portfolio is a ray-marched black hole with five bodies
around it: https://jonasjavier.dev/en. On phones it rendered at 1 pixel per
CSS point, on screens of 2.6 to 3. It looked soft. `setPixelRatio(devicePixelRatio)`
wasn't an option: a ray march pays per pixel, and 1 → 3 is nine times the work.

So the scene doesn't guess. It tries.

- It starts at 1 and tries `1 → 1.25 → 1.5`, never above `devicePixelRatio`.
- It measures windows of 45 frames, skips the 30 frames after each change,
  and reads the 75th percentile of the rAF interval.
- A step that doesn't hold is undone **and that ceiling stays closed** for
  the visit. Every change resets my temporal accumulation, and flip-flopping
  shows up as grain.

The bug that taught me the most: my first bar was fixed (p75 ≤ 18.5 ms =
"fast"). On a 120 Hz phone, 16.7 ms is half the screen's rate, and the
governor kept stepping up with the GPU at its limit. Taps felt late. Now the
bar is relative: the fastest pace seen this visit, with 15 % tolerance.

```ts
pace = Math.min(pace, p75);
const held = p75 <= pace * PACE_TOLERANCE; // 1.15
if (index > 0 && (p75 >= SLOW_MS || !held)) {
  index -= 1;
  ceiling = index; // never try this step again
}
```

Measured on a real GPU at 412 × 915 (density 2.625), the first version
climbed from 1 to its top step in about 6 s, and with 30 ms of injected work
per frame it fell back to 1 in about 7 s. Since October it also runs on desktop monitors scaled above 1.

What isn't solved: rAF only tells me when a phone is *below* its refresh
rate, not how much room is left above it. A phone right on the edge tries
1.25 once, fails, and shows one flash of grain. And I don't own a 120 Hz
phone: that case is pinned by unit tests with fake timestamps.

Has anyone found a better headroom signal on mobile WebGL without
`EXT_disjoint_timer_query`?
